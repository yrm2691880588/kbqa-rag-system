# KBQA-RAG · 电商知识库问答系统

一个从 0 到 1 独立搭建的 **RAG（检索增强生成）智能问答系统**：把商品说明书、价格表、营销文档等资料传进知识库，AI 就能基于这些资料准确回答用户问题，并像打字机一样实时输出回答。

> 面向「知识库问答」场景的完整落地实践，覆盖 账号体系 → 文档解析 → 向量检索 → AI 生成回答 的完整链路。

|------|------|------|

| 📚 知识库管理 | 建库 / 传文档 / 入库解析 | 一个账号可建多个知识库，文档按库隔离 |
| 📄 多格式解析 | Word / PDF / Excel / Markdown / 网页 | 自动抽取正文，表格行也参与检索 |
| 🧠 向量化入库 | 智能切块 + 嵌入向量 | 阿里云百炼 `text-embedding-v4`（1024 维） |
| 🔍 精准召回 | 向量检索 + 多召回候选 + 文档级去噪 | 相似度阈值 0.45 + 相对过滤，避免"张冠李戴"混入无关文档；可选接入重排模型精挑 |
| 💬 流式问答 | SSE 打字机效果 | 实时返回「思考 → 回答」，带来源依据 |
| 🧼 对话体验 | 闲聊识别 / 意图识别 / 重新生成 / 对话搜索 | 寒暄不查库；问"有什么商品"直接列清单；回答不满意可换个答案重答；历史对话支持全文搜索 |
| 👍 用户反馈 | 赞 / 踩 + 原因分类 | 点踩时收集"哪里不准确"（7 类原因）+ 补充说明，用于定位该补资料还是该调检索 |
| 📊 数据概览 | 用量 / 答上率 / 满意率 / 趋势 | 管理员一进来就能看到系统整体状况，以及待处理的失败文档与负面反馈 |
| 🖥️ 管理后台 | 会话 / 知识库 / 成员 / 日志 / 反馈 / 组织 | 前后端分离，接口幂等设计；支持批量上传（一次最多 50 个文件） |

## 🛠️ 技术栈

| 层次 | 技术 | 用途 |
|------|------|------|
| 后端框架 | **FastAPI** + Uvicorn | 高性能异步 API 服务 |
| 数据库 | **PostgreSQL 16**（Docker） | 用户 / 会话 / 消息 / 知识库元数据 |
| 向量库 | **Qdrant**（Docker） | 存储文档切块的高维向量，做相似度检索 |
| ORM | SQLAlchemy 2.0（async） | 异步数据库访问 |
| 文档解析 | PyMuPDF / python-docx / openpyxl / BeautifulSoup | PDF / Word / Excel / HTML 解析 |
| 切块 | langchain-text-splitters | 长文档智能分块 |
| 向量模型 | 阿里云百炼 DashScope `text-embedding-v4` | 文本 → 1024 维向量 |
| 对话模型 | DeepSeek `deepseek-v4-flash` | 基于检索结果生成回答 |
| 前端 | **Vue 3** + TypeScript + Vite | SPA 界面 |
| UI 组件 | Element Plus + Pinia + Vue Router + Axios | 组件库 / 状态管理 / 路由 / 请求 |
| 鉴权 | JWT（PyJWT）+ argon2-cffi | 双令牌刷新机制 |

## 🏗️ 系统架构

```
┌─────────────────────────────────────────────────────────┐
│  前端 Vue3 (Vite)           http://127.0.0.1:5173*      │
│  登录 / 知识库 / 聊天界面                                 │
└──────────────────────┬──────────────────────────────────┘
                       │ REST + SSE(流式)
┌──────────────────────▼──────────────────────────────────┐
│  后端 FastAPI           http://127.0.0.1:8000  /docs *  │
│                                                         │
│  ① 文档入库链路:  解析 → 切块 → 向量化 → 写入 Qdrant      │
│  ② 问答链路:      问题 → 向量检索 → 文档去噪 → 生成回答    │
│  ③ 体验模块:      闲聊识别 / 开放意图识别 / 会话记忆        │
└───────┬───────────────────────────┬─────────────────────┘
        │                           │
┌───────▼─────────┐      ┌──────────▼──────────┐
│  PostgreSQL 16  │      │  Qdrant 向量库       │
│  业务数据        │      │  文档向量 + 检索      │
└─────────────────┘      └─────────────────────┘
```

> \* 端口可在项目根目录 `.env` 的 `FRONTEND_PORT` / `BACKEND_PORT` 修改。
> 开发机上 8000/5173 常被其他项目占用，撞车时启动脚本会提示并给出改法。

**问答核心流程（RAG）**

1. 用户提问 → 后端先做**意图判断**（寒暄？开放列举？还是真问题？）
2. 真问题 → 问题文本转成向量 → 到 Qdrant 里取回最相似的候选片段
3. **文档级去噪**：候选片段先按"文档"归类，剔除明显低于同文档最佳命中的噪声片段
4. 命中片段 + 系统提示词 拼给 DeepSeek → 生成带依据的回答，SSE 流式返回
5. 没命中 → 明确回答"知识库中没有相关信息"，不乱编

## 🚀 快速启动

### ⭐ 最省事：双击两个脚本（推荐）

项目根目录有两个一键脚本，**不用记命令、不用找脚本在哪**：

| 脚本 | 作用 |
|---|---|
| **[启动.bat](启动.bat)** | 自动完成：检查环境 → 起数据库容器并等健康 → 起后端并等就绪 → 起前端 → 打开浏览器 |
| **[停止.bat](停止.bat)** | 一键停掉前后端进程 + 数据库容器（**数据保留**，下次启动还在） |

**第一次使用**，仍需先做两步准备：

1. 配置密钥：把 `backend/.env.example` 复制成 `backend/.env`，
   填入你自己的 `EMBEDDING_API_KEY`（阿里云百炼）与 `LLM_API_KEY`（DeepSeek）
2. 装依赖：`cd frontend` 然后 `npm install`

之后每天只要**双击「启动.bat」**即可。

### 端口被别的项目占用？

开发机上常常同时跑着好几个项目，`8000`/`5173`/`5432` 这几个端口最容易撞车。
本项目**不会去抢别人的端口**，端口都可以在项目根目录的 `.env` 里改：

```ini
# 数据库在宿主机上的端口（默认 5432，撞车就改）
POSTGRES_HOST_PORT=5433
# 后端端口（默认 8000）
BACKEND_PORT=8010
# 前端端口（默认 5173）
FRONTEND_PORT=5180
```

改完之后：

| 改的是 | 还要同步改哪里 |
|---|---|
| `POSTGRES_HOST_PORT` | `backend/.env` 里 `DATABASE_URL` 的端口号要一致 |
| `BACKEND_PORT` | 不用改，前端代理会自动跟着（`vite.config.ts` 读同一个配置） |
| `FRONTEND_PORT` | 不用改 |

启动脚本会**先探测端口**：如果发现被别的程序占了，会直接告诉你是谁占了、怎么改，
而不是丢一句"启动失败"让你猜。

脚本的几个贴心设计：

- **已运行的部分自动跳过**，不会重复开窗口
- **等真正就绪才开浏览器**，不会出现白屏
- **停止时按 PID 精确识别**，绝不按进程名批量杀，不会误伤你机器上别的项目

### 手动启动（4 步）

> 需要自己控制每一步时用这个。每一步都给了完整命令，复制即可。

#### 0. 环境要求

| 依赖 | 版本 | 用途 |
|------|------|------|
| Docker Desktop | 任意较新版本 | 跑 PostgreSQL + Qdrant |
| Python | 3.11+（实测 3.12） | 后端 |
| Node.js | 18+ | 前端构建 |

#### 1. 配置密钥（只需一次）

```bash
cd backend
copy .env.example .env        # Windows
# 然后把 .env 里的两个 Key 填成你自己的：
#   EMBEDDING_API_KEY = 阿里云百炼 Key（向量模型，必填）
#   LLM_API_KEY       = DeepSeek Key（对话模型，必填）
# 申请地址见 .env.example 内注释
```

#### 2. 启动数据库（Docker）

```bash
docker compose up -d
```

会启动两个容器：`kbqa-postgres`（5432）与 `kbqa-qdrant`（6333/6334）。

#### 3. 启动后端

```bash
# 建议先建虚拟环境并装依赖：
python -m venv .venv
.venv/Scripts/pip install -r backend/requirements.txt

# 启动后端
# 端口与根目录 .env 的 BACKEND_PORT 保持一致（默认 8000）
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

后端就绪后：
- API 文档（Swagger）：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:8000/api/v1/health

> 若根目录 `.env` 里改了 `BACKEND_PORT`，上面两处地址的端口要同步替换。

#### 4. 启动前端

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 **http://127.0.0.1:5173** 即可使用（端口受 `.env` 的 `FRONTEND_PORT` 控制）。

> 💡 如果你不想手动跑上面四步，直接双击根目录的 **[启动.bat](启动.bat)** 即可：
> 它会按「Docker → 数据库 → 后端 → 前端 → 健康检查」的顺序自动完成，
> 并等每一步真正就绪后才继续（不是简单地把窗口开起来）。
> 关闭时双击 **[停止.bat](停止.bat)** 一键全停。

## 📝 使用流程（第一次体验）

1. 打开 http://127.0.0.1:5173 → **注册账号**
2. 进入知识库 → **新建知识库**（如"商品资料库"）
3. 在知识库内**上传文档**：可直接使用 `样例资料/` 目录里的文件
   （`商品总览.md`、`星翼智能手表Watch2手册.pdf`、`星翼蓝牙耳机Pro说明书.docx`、`星耀空气净化器A8.md`、`星翼数码商品价格表.xlsx` 等）
4. 等文档状态变为"已入库" → 进入**聊天**，选择该知识库
5. 开始提问，例如：
   - "Watch2 的电池续航怎么样？"（具体问答）
   - "介绍一下本商品的型号和价格"（开放意图 → 自动列出商品清单）
   - "你好"（闲聊 → 不查库，正常打招呼）
